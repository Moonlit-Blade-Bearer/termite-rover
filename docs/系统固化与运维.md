# 系统固化与运维（T2.2 收尾 / T12.1）

> 目标：**开机即用**。断电重启后不需要人工敲任何命令，全链路自己起来；单点崩溃能自愈。

## 一、启动链

```
宿主开机
  └─ Docker 守护进程
       └─ termite_ros2 容器（restart: unless-stopped 自动拉起）
            └─ /root/docker/entrypoint.sh
                 ├─ source /opt/ros/humble/install/setup.bash
                 ├─ source /root/ros2_ws/install/setup.bash
                 ├─ bash /root/docker/fixes.sh        # 幂等补丁
                 ├─ 等 /dev/rrc（最多 30s）
                 └─ exec ros2 launch termite_bringup mapping.launch.py
                      ├─ ros_robot_controller   （底盘驱动，/dev/rrc 1M）
                      ├─ odom_publisher         （/odom_raw）
                      ├─ ekf_node               （/odom + odom→base_footprint）
                      ├─ static_tf_pub          （base_footprint→base_link→{imu_link,laser}）
                      ├─ rplidar_node           （/scan，by-id 串口）
                      └─ slam_toolbox           （/map + map→odom）
```

所有节点 `respawn=True`：单个进程崩溃 2–3 秒后由 launch 自动拉起。
launch 本身挂掉 → 容器 PID 1 退出 → Docker 按 `unless-stopped` 重启容器。

## 二、镜像与依赖固化

基础镜像 `dustynv/ros:humble-ros-base-l4t-r32.7.1` 缺以下运行时依赖，容器重建就会丢，所以固化在 `docker/Dockerfile`：

| 依赖 | 用途 |
| --- | --- |
| `libgeographic17` | robot_localization EKF 的 `libGeographic.so.17` |
| `libboost-system/serialization/thread 1.65.1` | slam_toolbox |
| `libtbb2` | slam_toolbox 的 TBB |
| `libceres1` + `libgoogle-glog0v5` | slam_toolbox 的 Ceres 求解器插件 |
| `pyserial 3.5`（pip） | ros_robot_controller 串口驱动 |

构建：
```bash
docker build -t termite-ros:humble-l4t-r32.7.1 ~/termite-rover/docker
```

注意：基础镜像自带一个 **GPG 密钥已过期** 的 ROS apt 源（`packages.ros.org`），会让 `apt-get update` 直接失败。Dockerfile 里已删掉该源（ROS 本体是预编译在 `/opt/ros/humble/install` 的，不需要它）。

## 三、非持久补丁（`docker/fixes.sh`）

每次容器启动自动执行，可重复运行：

1. **rclcpp `client.hpp`**：GCC 7 下 `std::optional<std::variant>` 隐式转换编译失败，改 `get_and_erase_pending_request()` 的返回语句。robot_localization / interactive_markers / slam_toolbox 编译时都会踩到。
2. **interactive_markers 头文件双层目录**：安装到 `include/interactive_markers/interactive_markers/`，用同名软链摊平。
3. **pyserial 兜底**：镜像里装失败时，从 `~/ros2_ws/vendor/*.whl` 离线安装。

## 四、看门狗三层

| 层级 | 机制 |
| --- | --- |
| 节点 | `respawn=True, respawn_delay=2~3s` |
| 容器 | `restart: unless-stopped` + compose healthcheck（launch 进程存活） |
| 宿主 | `termite-watchdog.timer` 每 2 分钟：容器没跑就 `docker start`；`/odom` 连续 3 次无数据就 `docker restart`；**`/dev/rrc` 不存在时跳过**（避免没接车时反复重启） |

查看看门狗日志：
```bash
journalctl -t termite-watchdog -n 20 --no-pager
systemctl list-timers | grep termite
```

## 五、日常操作

```powershell
# PC 侧：同步源码/脚本到 Jetson 并编译（改完代码就跑这个）
powershell -ExecutionPolicy Bypass -File scripts\deploy.ps1
```

```bash
# Jetson 侧
bash ~/termite-rover/scripts/health.sh        # 一键体检：节点/话题频率/地图/TF
docker logs -f termite_ros2                    # 看全部节点日志
docker restart termite_ros2                    # 重启整条链路
docker exec -it termite_ros2 bash              # 进容器

# 只起底盘（不建图）
ros2 launch termite_bringup robot.launch.py
# 建图（默认 by-id 雷达口，可覆盖）
ros2 launch termite_bringup mapping.launch.py lidar_port:=/dev/ttyUSB0

# 手柄遥控（接收器插 Jetson USB 口）
ros2 launch termite_bringup teleop.launch.py source:=js
```

## 五之二、手柄遥控

硬件：飞智八爪鱼5 + 2.4G 接收器，接收器插 **Jetson** 的 USB 口（不是控制板）。

**为什么需要额外配置**：Jetson 内核的 `xpad` 是内置驱动，但白名单里没有飞智的 `37d7:2501`，接收器的 XInput 接口（class ff / subclass 5d / protocol 01）没有驱动接管，Linux 只会把它当键盘鼠标。解决方法是把 VID/PID 写进 `new_id`：

```bash
echo 37d7 2501 | sudo tee /sys/bus/usb/drivers/xpad/new_id
# 生效后 dmesg 出现 "Generic X-Box pad"，/dev/input/js0 出现
```

已持久化，无需手动执行：

- `/etc/systemd/system/termite-xpad.service`（开机写 `new_id`）
- `/etc/udev/rules.d/99-flydigi-xpad.rules`（热插拔时拉起上面那个服务）
- 安装/更新：`scripts/deploy.ps1` 同步到 `~/termite-rover/scripts/` 后手动 cp 到 `/etc`（见提交记录）

**节点**（容器内没有 `joy` 包，均为自写）：

| 节点 | 作用 |
| --- | --- |
| `linux_joy` | 读 `/dev/input/jsX` → 发布 `/joy`，50Hz，掉线自动重开设备 |
| `joy_teleop` | `/joy` → `/cmd_vel`，死区 0.08、限速 ±0.15 m/s / ±0.4 rad/s、0.5s 无数据归零 |

**实测轴映射**（八爪鱼5 / XInput）：`axis0`=左摇杆X，`axis1`=左摇杆Y（上推 = -1），`axis3`=右摇杆X（右推 = +1），`axis4`=右摇杆Y（上推 = -1），`axis2/5`=LT/RT（松开 = -1），`axis6/7`=十字键。

**操作**：左摇杆前后 = 前进后退，右摇杆左右 = 转向。改方向/限速编辑 `config/teleop.yaml`（`ros2 run` 不读 yaml，改代码默认值或走 launch）。

## 六、断电恢复测试（验收步骤）

1. 接好控制板（`...3600` 口）和雷达；
2. `sudo reboot`；
3. 等 2–3 分钟（Jetson Nano 起得慢）；
4. PC 侧跑 `bash ~/termite-rover/scripts/health.sh`，应看到：
   - `/scan` ≈6.7Hz、`/odom` ≈30Hz、IMU ≈19.6Hz
   - `/map` 有宽高
   - `map → base_link` TF 通

## 七、已知限制

- **Jetson 无 RTC 电池**：断电后开机时间会跳变，NTP 校正前的 rosbag 时间戳不可信（T10.1 统一时基时处理）。
- 容器内 `/etc/bash.bashrc` 会打印 `COLCON_TRACE: unbound variable`，是基础镜像自带噪音，不影响功能。
- RPLIDAR A1 实测 ≈6.7Hz（硬件上限），建图够用。
